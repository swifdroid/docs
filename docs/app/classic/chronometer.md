# Chronometer

`Chronometer` is Droid's classic elapsed-time display. The current wrapper inherits `TextView` and exposes base time, display formatting, count-up/count-down mode, start/stop control, and tick-listener bridging.

## Use it when…

Use a chronometer for call duration, recording time, workout timers, or other UI where Android should maintain a continuously updating elapsed-time label.

## How it behaves

`base(_:)`, `format(_:)`, `countDown(_:)`, `started(_:)`, and `onChronometerTickListener(_:)` are queued Droid view properties.

Getters plus `start()` and `stop()` operate on the live Android instance.

Because `Chronometer` inherits `TextView`, the normal text styling and layout modifiers remain available.

## Examples

### Configure the displayed timer

```swift
Chronometer()
    .format("Elapsed: %s")
    .countDown(false)
```

### Start and stop a mounted chronometer

```swift
let timer = Chronometer()
    .format("%s")

timer.start()
timer.stop()
```

`start()` and `stop()` require a live Android instance. Builder-time configuration should use the queued setters.

## Initializers

```swift
Chronometer()
Chronometer(id: 1001)
```

## Methods

### Base time

`base(_:)` queues the Android base time used by the chronometer. `base()` reads the current live value.

### Formatting

`format(_:)` configures the display format. `format()` reads the current format string.

`contentDescription()` reads the live accessibility description generated by Android.

### Count direction and started state

`countDown(_:)` configures whether the chronometer counts down toward its base instead of up from it.

`countDown()` and `isCountDown()` read the current live mode.

`started(_:)` queues Android's started state, while `start()` and `stop()` are immediate live-instance actions.

### Tick listener

`onChronometerTickListener(_:)` accepts a JNI-compatible Android listener object and queues it for the view.

`onChronometerTickListener()` returns the current live listener object as `JObject?`.

Droid exposes the listener bridge but does not construct the listener object for you.

### Lower-level helpers

The wrapper also exposes visibility/window lifecycle hooks and `isTheFinalCountDown()` for lower-level integrations.
