# Source Verification Skill

Use when authoring or materially changing a technical page.

1. Identify the exact documented type/API/behavior and owning sibling repository.
2. Inspect current owning source directly; do not rely on filenames, docs, tracking rows, or an agent report.
3. Record only the source facts required for user-facing explanation: exact Swift surface, behavior, lifecycle/availability/limitations as relevant.
4. Draft/update the page according to `WRITING_GUIDELINE.md`.
5. Re-check every code example and technical claim against source.
6. If source is incomplete/ambiguous, stop that claim/page path and update tracking state rather than guessing.
7. Sibling source inspection is read-only unless separately authorized.
